# 컴시간알리미 시간표 자동 동기화 설계

작성일: 2026-08-21
대상 실습: 2027년 5월 교육실습

## 배경

시간표 변동은 학교가 컴시간알리미로 최종 확정한다. 지금까지는 변동이 생길 때마다
사람이 `scheduleOverrides` 를 손으로 고쳐 커밋했다. 2026년 5월 실습에서만 20건 넘게
발생했다. 이 과정을 매일 자동으로 처리한다.

## 데이터 출처

컴시간 웹 API를 쓴다. 로컬 `C:\Program Files (x86)\알림이\dat\tmp\*.kim` 바이너리도
같은 데이터를 갖고 있으나, 웹 API는 해독이 불필요하고 PC 전원 상태와 무관하다.

```
학교검색  GET http://comci.net:4082/36179?17384l<EUC-KR 퍼센트인코딩 학교명>
시간표    GET http://comci.net:4082/36179?<base64("73629_<학교코드>_0_<주차r>")>
```

응답은 UTF-8 JSON이며 뒤에 쓰레기 바이트가 붙는다. 마지막 `}` 까지 잘라서 파싱한다.

서울사대부설여자중학교 = 학교코드 **38761**. 로컬 `.kim` 데이터와 대조하여 확인했다.

| 항목   | 컴시간 웹           | 로컬 / 저장소                     |
| ------ | ------------------- | --------------------------------- |
| 학급수 | `[18,6,6,6]`        | 101~106, 201~206, 301~306         |
| 교사수 | 44                  | `교사명.kim` 44명, 배열 순서 동일 |
| 과목명 | 36개                | `과목명.kim` 동일                 |
| 수정일 | 2026-08-21 12:48:13 | `dat/tmp` mtime 동일              |

### 응답 필드

| 필드                            | 뜻                                          |
| ------------------------------- | ------------------------------------------- |
| `자료481[학년][반][요일][교시]` | 기본 시간표                                 |
| `자료147[학년][반][요일][교시]` | 당일 실제 시간표. 변경된 슬롯은 값 앞에 `>` |
| `자료446[]`                     | 교사명 (인덱스 1부터)                       |
| `자료492[]`                     | 과목명 (인덱스 1부터)                       |
| `시작일`                        | 해당 주 월요일 (`YYYY-MM-DD`)               |
| `분리`                          | 과목/교사 인코딩 제수. 현재 1000            |
| `자료244`                       | 컴시간 측 최종 수정일시                     |
| `일자자료`                      | 조회 가능한 주차 목록                       |

슬롯 값 디코딩:

```
교사 인덱스 = v % 1000
과목 인덱스 = floor(v / 1000) % 분리
```

요일은 1=월 … 5=금. 실측 검증: `1001 → 국어A/이현진`, `33044 → 진로/문인숙`,
`24028 → 체육A/엄인우`.

## 제약

1. **조회 범위 2주.** `일자자료` 는 이번 주와 다음 주만 준다. 매일 실행하면 모든
   날짜가 도착 전 약 10회 점검되므로 누락은 없으나, 먼 미래 변동의 사전 통지는
   최대 2주로 제한된다.
2. **교사명 마스킹.** 웹 API는 `이현*` 처럼 성+1자만 준다. 44명의 마스킹값이 모두
   유일하므로 저장소 교사 명단과 1:1 매칭이 가능하다. 매 실행마다 이를 검증한다.
3. **학기 교체.** 저장소 기본 시간표는 2026년 1학기 데이터다. 2027년 3월 학기 시작
   후 `자료481` 로 기본 시간표를 다시 생성해야 한다.

## 저장 위치

| 데이터      | 위치                                   | 이유                      |
| ----------- | -------------------------------------- | ------------------------- |
| 기본 시간표 | `src/lib/timetableData.ts` (커밋)      | 학기당 1회만 변함         |
| 변동분      | Firestore `timetable_overrides/{날짜}` | 매일 변함. 배포 없이 반영 |

기존 `scheduleOverrides` 상수는 **삭제하지 않는다**. Firestore 값을 그 위에 병합한다.
Firestore가 비어 있으면 현재와 동일하게 동작하므로 배포가 무해하고, 2026년 5월
기록을 옮기는 마이그레이션도 필요 없다. 날짜가 겹치면 Firestore가 이긴다.

### 스키마

```
timetable_overrides/{2027-05-11}
  date: "2027-05-11"
  slots: { "101": { "3": { teacher, subject, prevTeacher, prevSubject } } }
  syncedAt, comciModifiedAt

sync_runs/{2027-05-10T17:00:00+09:00}
  status: "OK" | "SKIPPED" | "ABORTED" | "ERROR"
  comciModifiedAt, datesChecked, slotsChanged, applicationsCancelled, message
```

## 동기화 절차

1. `r=1`, `r=2` fetch.
2. `자료244` 가 직전 성공 실행과 같으면 `SKIPPED` 로 조기 종료.
3. 교사 마스킹 매핑 검증. 44명이 1:1로 유일 매칭되지 않으면 `ABORTED`.
4. 기본 시간표 정합성 검증. 컴시간 `자료481` 과 저장소 `timetableData` 가 다르면
   `ABORTED` 후 "학기 시간표가 바뀌었습니다. 재수입이 필요합니다" 알림.
5. 대상 날짜 = `[내일 … +14일] ∩ 실습기간 ∩ 평일`.
6. 슬롯별 diff. 변경분과 복원분(컴시간이 원래대로 되돌린 경우)을 모두 낸다.
7. 변경 건수가 30건을 넘으면 `ABORTED`.
8. Firestore 반영. 변경 0건이면 아무것도 쓰지 않는다.
9. 영향받은 `observation_applications` 를 `status: "CANCELLED"`,
   `cancelReason: "TIMETABLE_CHANGED"` 로 전환.
10. 알림 발송.
11. `sync_runs` 기록.

4번이 폭주 방지의 핵심이다. 이 검증이 없으면 학기가 바뀐 순간 전 슬롯이 변동으로
잡혀 시간표 전체를 덮어쓴다.

## 실행

`.github/workflows/sync-comcigan.yml`, cron `0 8 * * 1-5` (UTC 08:00 = KST 17:00).

## 안전장치

- `--dry-run` 으로 쓰기 없이 diff만 출력.
- 모든 쓰기는 날짜 단위 doc merge. 재실행해도 결과가 같다.
- 변경 건수 상한과 기본 시간표 정합성 검증으로 대량 오염을 막는다.

## 테스트

1. 디코더. 실측값 고정: `1001 → 국어A/이현진`, `33044 → 진로/문인숙`.
2. diff 엔진. 픽스처 2건으로 변경분과 복원분을 확인.
3. 정합성 가드. 기본 시간표 불일치 시 `ABORTED`.
4. 멱등성. 같은 입력을 두 번 넣으면 두 번째 쓰기는 0건.

## 운영 준비 (사람이 해야 하는 일)

동기화는 아래 세 가지가 갖춰져야 실제로 돈다. 그 전까지는 매 실행이 `SKIPPED`
로 끝나므로 지금 상태로 두어도 아무 일도 일어나지 않는다.

### 1. Firestore 보안 규칙

`timetable_overrides` 를 로그인 사용자가 읽을 수 있어야 한다. 규칙은 저장소가 아니라
Firebase 콘솔에서 관리한다. 확인된 사항: 규칙이 없으면 앱이 `permission-denied` 를
받고 정적 시간표로 되돌아간다(동작은 하지만 변동분이 보이지 않는다).

```
match /timetable_overrides/{date} {
  allow read: if request.auth != null;
  allow write: if false;          // 서비스 계정만 쓴다
}
match /sync_runs/{run} {
  allow read: if request.auth != null;
  allow write: if false;
}
```

### 2. GitHub Secrets

| 이름                       | 내용                                   | 필수   |
| -------------------------- | -------------------------------------- | ------ |
| `FIREBASE_SERVICE_ACCOUNT` | 서비스 계정 JSON 전문                  | 예     |
| `ADMIN_CHAT_WEBHOOK`       | 관리자 요약을 받을 Google Chat webhook | 아니오 |

### 3. 실습 기간과 학기 데이터

`src/lib/comcigan/config.ts` 의 `INTERNSHIP_START` / `INTERNSHIP_END` 를 확정된
실습 일정으로 고친다. 현재는 2027-05-01 ~ 2027-05-31 로 두었다.

2027년 3월 학기가 시작되면 다음을 다시 만들어야 한다. 그 전까지는 기본 시간표
정합성 검증이 걸려 `ABORTED` 로 멈춘다(의도된 동작이다).

- `src/lib/timetableData.ts` 의 기본 시간표 — 컴시간 `자료481` 로부터
- `src/lib/comcigan/roster.ts` 의 교사 명단 — 컴시간 교사 배열 순서대로

## 확인한 것과 확인하지 못한 것

확인함:

- 컴시간 웹 API 로 학교 데이터 조회 (학교코드 38761)
- 디코딩 정확성 — 로컬 `.kim` 파일과 교사·과목·학급 구성 일치
- 변동 감지 — 2026-08-17 주간 실측에서 24건 검출
- 기본 시간표 정합성 가드 — 학기가 다른 현재 데이터로 501건 불일치 감지 후 중단
- 휴일 처리 — 광복절 대체휴일(2026-08-17)을 전 슬롯 결강이 아니라 건너뛰기로 처리
- 멱등성 — 같은 입력 2회 실행 시 2회차 변경 0건
- 로그아웃 상태에서 앱이 기존과 동일하게 동작

확인하지 못함:

- Firestore 실제 쓰기 — 서비스 계정 키가 없어 실행하지 못했다
- 신청 자동 취소와 알림 발송 — 위와 같은 이유
- 로그인 상태의 앱 화면에서 변동분이 표시되는 모습

실습 시작 전에 `--dry-run` 으로 한 번, `workflow_dispatch` 수동 실행으로 한 번
점검하는 것을 권한다.
